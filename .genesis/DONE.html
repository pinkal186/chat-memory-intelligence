1 · The Locked Spec (what we are building)

Cognitive job: Reduce information loss across conversations by selectively extracting, evaluating, storing, and retrieving user-specific memories (preferences, projects, facts) so a future conversation doesn't require the user to repeat context — while storing only what improves a future decision (memory-system.html, L0/L5).

Inputs: raw conversation turns, uploaded documents, user corrections/deletion requests  →  Outputs: a ranked context block of relevant memories injected into the next response

Autonomy level: full automation on capture/evaluate/retrieve (mechanical, no judgment call needed)  |  Human-in-the-loop points: user can correct a wrong memory ("no, I moved"), explicitly say "forget that," and low-confidence memories are flagged rather than silently trusted

Failure tolerance: must degrade gracefully — memory retrieval failure must never block a response; a wrong memory delivered with confidence is worse than no memory (memory-system.html, §0.1 Step 4)  |  Trust boundary: yes — every memory is scoped to one user_id; single-tenant acceptable for M1-M2, but no cross-user leakage is a day-one invariant (M3)

Filled during Genesis step G0 (Cognitive Design) via agentic-swe-master.

2 · Definition of Done (binary gates — checked by the VERIFIER, not the maker)

Gates below are pulled from every phase of memory-system.html's 20-phase production lifecycle (§0.4) that applies to this project. Phases not yet in scope are listed separately further down so the verifier never blocks a milestone on a phase that hasn't started.

Phase 0 Cognitive Design — cognitive job (§1 above) is written and justified before any code exists (memory-system.html L0)
Phase 1 System Architecture — the six subsystems (Capture, Storage, Retrieval, Evaluation, Decay, Governance) stay boundary-clean; no subsystem's responsibility bleeds into another (L3 / modular-architecture gate)
Phase 3 Backend & API — write path (Extractor → Evaluator → Store) and read path (Retriever → Ranking → Context Composer → Response LLM) implemented exactly as the documented state machine (L2 / L9)
Phase 4 Workflow Orchestration — the write-path job runs through an orchestration engine (Temporal/Celery) with retries and timeouts, never a bare synchronous function call (§2.1 layer 10)
Phase 5 LLM & Reasoning — extractor/evaluator prompts emit structured JSON only, validated against a schema; model is instructed to say "I could not find information about X" rather than guess (§0.2 failure mode 1 / llmops gate)
Phase 6 Memory Architecture — four storage tiers respected (working / session / long-term / knowledge); every record carries the typed taxonomy fields (episodic/semantic/procedural) plus importance, confidence, source (L1 / L2 / L4)
Phase 9 Evaluation Systems — a golden set exists and retrieval precision ≥ 90%, recall measured; a regression test pins at least one known retrieval case (§4.1 SLOs, §3.1 Phase 18 example)
Phase 10 Observability — retrieval rate, correction rate, retrieval latency, and cost per write/retrieval are emitted as metrics on every request (§3.1 Phase 10)
Phase 11 Security Architecture — every query is scoped by user_id (row-level security), a PII filter blocks secrets/credentials before write, sensitive memory encrypted at rest (§3.1 Phase 11 / security gate)
Phase 12 Reliability Engineering — memory retrieval failure degrades to an answer without memory (timeout + circuit breaker), verified by a chaos/failure test, never blocks response generation (§3.1 Phase 12 / production-readiness gate)
Phase 15 Governance & Compliance — append-only audit log on every write/read/delete; a deleted memory is never retrieved again (§3.1 Phase 15)
Phase 16 Economics — cost is measured per useful memory, not raw count; the write-gate and decay job are treated explicitly as cost controls (§3.1 Phase 16)
Phase 18 CI/CD for AI — an eval gate blocks any change that regresses the golden-set score; shadow mode available before switching traffic to a new extractor/ranking version (§3.1 Phase 18)
Phase 19 Human-in-the-Loop — a user correction ("no, I moved") flows back as a memory update; an explicit "forget that" actually deletes the memory (§3.1 Phase 19)
Four hard invariants never violated: no cross-user leakage · deleted memories never retrieved · retrieval failure never blocks a response · every memory has provenance (§4.1 "Invariants" / context-graph.json)
SLO band held: availability ≥ 99.9%, retrieval latency p95 < 100ms, retrieval precision ≥ 90% (§4.1 "SLOs and SLAs")

One verify pass by a separate agent/model (L4)
