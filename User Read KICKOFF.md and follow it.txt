User: is this possible to sql injection text may be distub sql query?

GitHub Copilot: Short answer: unlikely with the current code, but it would be possible if someone later builds SQL by concatenating user text.

Why it's safe now
- `SQLiteMemoryStore.add`, `query_by_user`, and `delete_by_id` use parameterized queries (placeholders), so user content is passed as parameters — not interpolated into SQL — which prevents classic SQL injection.
- The DDL in `_ensure_table` is static SQL (no user input).
- The extractor/evaluator only produce text stored via the parameterized `INSERT`.

When it could become vulnerable
- If any code later builds SQL with string interpolation / f-strings (e.g., `f"SELECT ... WHERE content LIKE '%{user_text}%'"`), or uses `.execute()` on user-supplied SQL, injection becomes possible.
- Using unsafe helpers that implicitly format SQL (some naive helpers/templating) will also open risks.

Recommendations (short)
- Always use parameterized queries (keep doing what we do).
- Use a safe DB client/ORM for Postgres (e.g., `psycopg`/`asyncpg` with parameters or `SQLAlchemy`) and never-format SQL with user input.
- Validate or canonicalize types where possible (e.g., `user_id` should be validated).
- Use least-privilege DB credentials.
- Add a regression test that tries malicious payloads (see below).
- When moving to Postgres + `pgvector`, follow the same parameterized pattern for vector inserts/queries.
